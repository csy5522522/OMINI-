# Omini工具箱

Windows 桌面工具箱。包含下载中心、校园网、课表、超级备忘录、多电脑文件夹同步和 AI 编程助手。

当前版本 **1.2.3**。[下载 Windows 安装包](https://github.com/csy5522522/OMINI-/releases/tag/v1.2.3)。更新内容见 [CHANGELOG.md](CHANGELOG.md)，发布流程见 [版本管理说明](docs/RELEASING.md)。

## 统一账号与超级备忘录

网页入口：https://my.omini.cn。管理入口：https://my.omini.cn/admin。

桌面侧栏点击「邮箱注册 / 登录」，或进入「设置 → 邮箱账号与网页端」，点击「连接官方云端」后填写邮箱及密码进行注册或登录。注册需再次确认密码，登录后在「超级备忘录」使用同一账号的文字、图片与历史版本。网页端提供相同的注册和登录功能。邮箱是账号标识，本版未接入邮件验证码。

超级备忘录支持自动保存、插入/粘贴 PNG、JPEG、GIF、WebP 图片、搜索、重命名、TXT 导入导出、回收站和历史回滚。每次写入、删除和回滚追加快照，回滚会创建新版本。桌面每 20 秒同步一次，或点击「立即同步」；离线期间的动作保存在本机，恢复连接后逐个上传。多端同时修改时保留冲突副本。图片最多 10 MB，每篇正文最多 2 MB。

备忘录采用左侧列表、右侧正文的文档工作台：文字与图片直接在同一正文中编辑。底部图标可插入图片，「更多」菜单提供立即保存、历史版本及移到回收站；Ctrl+S 可立即保存。桌面的 TXT 导入、另存为和重命名也在「更多」中，目录管理与导入本机备忘录位于左栏底部的工作区菜单。回收站内可只读浏览文字、图片和历史，再恢复备忘录。窄屏通过「返回列表」切换列表和正文。

未登录的本机加密备忘录与账号缓存分开保存。1.2.3 起，首次关联的账号登录时自动合并本机笔记、图片、全部历史和回收站，原文件保留；重复登录只合并新增动作，其他账号继续隔离。工作区菜单中的「导入本机备忘录」可手动合并其他目录，保留真实标题与历史。账号缓存按服务地址和账号隔离，自动保存至加密工作区，支持 TXT 导入与主动导出。

桌面「设置 → 可选功能加载」可勾选各项工具；网页「偏好设置」可勾选课表、超级备忘录和 AI 编程助手。保存后立即隐藏取消勾选的侧栏入口，并停止相关后台任务；桌面下载会暂停，个人数据保留。全部关闭时仍可使用设置和账号。登录后的主题、并发数与功能选择随账号同步。

同一邮箱账号可在多个客户端和网页间同步课表及学期日期、备忘录文字/图片/历史、助手连接配置、Codex 成员凭据与启停状态、调度/权重/模型、额度快照和操作记录。桌面每 15 秒同步账号工作区，备忘录每 20 秒同步；设置中可点击「立即同步全部账号数据」。网页新增「AI 编程助手」页面，可导入、停用、移出成员并修改账号池设置。账号池进程在各电脑本地运行。

账号工作区按服务地址与账号隔离。首次登录会复制本机课表和助手数据到首个账号，保留原文件；其他账号使用独立目录。离线修改保留，记住登录状态后可离线重启继续编辑。并发修改合并独立字段，同字段冲突保留云端值和加密备份，可在客户端「同步备份与恢复」或网页偏好设置恢复冲突字段。程序路径、下载目录、FFmpeg 安装位置、本地代理端口/密钥与进程运行状态按设备保留。

桌面「设置 → 可选组件 · 下载安装」提供 FFmpeg 和 CLIProxyAPI 账号池引擎的下载入口，同时保留官网/GitHub 链接。安装在当前用户目录，支持取消及失败重试，校验锁定版本的 SHA-256 后安装；FFmpeg 安装成功自动写入路径并检测，原有手动选择入口继续可用。

云端使用 Docker、MySQL 8.4 和 Nginx HTTPS。账号、图片、备忘录和动作快照持久保存在数据库；课表和偏好也按账号隔离。密码使用随机盐及 PBKDF2-SHA256（600,000 次）哈希保存。网页邮箱会话有效期 12 小时；桌面勾选记住登录后有效期 30 天，启动验证有效凭据时续期。凭据过期保留原账号工作区与本机编辑，重新登录后继续同步。桌面记住登录使用 Windows 本机加密，密码不保存。管理员后台支持账号启用、停用、重置密码与管理员密码修改。

也可在设置中配置自有服务，或填写 `http://127.0.0.1:18765` 后启动本机网页服务。安装版支持 `Omini工具箱.exe --web --open`，源码支持 `Start-Omini-Web.cmd`。Docker 配置与数据备份见 [部署说明](deploy/README.md)，网页功能见 [Web 使用说明](web/README.md)。

验证：`py -3.11 -m unittest tests.test_accounts tests.test_memos tests.test_desktop_settings tests.test_web_server -v`，`node tests/test_web_frontend.cjs`。

1.2.2 起，备忘录标题、正文、图片、历史及同步元数据使用带校验的 Fernet 存储加密。Windows 本机密钥由当前用户 DPAPI 保护；缓存镜像改为不含标题的 `.ominote` 密文文件。旧 TXT 和历史库首次打开会先创建加密恢复副本再迁移；原始导入文件、以前导出的 TXT 和旧备份需自行保管。主动「另存为 TXT」仍输出普通文本。浏览器未保存草稿加密存入 IndexedDB，旧 localStorage 草稿成功迁移后移除。服务器运行时解密以支持同步，这属于存储加密，并非端到端加密。

备份本机笔记时复制整个工作区（包括隐藏文件与 `.sqlite3.key`）；Windows 密钥绑定原用户，更换电脑前请在原电脑导出。服务器须同时备份数据库、`memo-storage.key` 和 `account-sync.key`，详见 [部署说明](deploy/README.md)。

课表周次（包含「全学期」）自动保存，刷新页面或重启客户端会恢复；同账号通过账号工作区双向同步。Web 端保留课表、备忘录及助手管理，下载中心已移除。桌面端保留下载中心，Omini API 与 Bright Data 已移除，旧个人配置保留在 AppData。

## 检查与安装更新

进入「设置 → 软件更新」，点击「检查更新」。程序从 `csy5522522/OMINI-` 的 GitHub 最新正式 Release 比较版本，发现新版后启用「下载更新」。下载支持进度和取消，完成后校验文件大小与 SHA-256；校验通过后点击「退出并安装更新」。工具箱完成下载任务处理、保存和后台服务退出后才启动安装向导。安装器沿用原安装位置，保留个人设置和同步数据。

仓库为私有时，每台电脑需要填写有权访问该仓库的 GitHub Token。建议使用仅选择此仓库、Contents 为只读的细粒度 Token；公开仓库可以留空。可勾选 Windows 本机加密保存；取消勾选并保存会移除已保存 Token。凭据只用于 GitHub API，下载跳转到 GitHub 文件分发域名时不转发 Token，安装包不内置账号凭据。

更新配置位于 `%APPDATA%/Omini工具箱/updates/credentials.json`，安装包缓存位于同目录的 `downloads/版本号/`。下载安装前均校验文件完整性，不自动安装较旧版本、预览版或缺少校验信息的附件。更新源使用 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。

从旧版首次升级到带此按钮的 1.1.2，请先手动运行一次新安装包；之后可在程序内检查和下载安装后续版本。测试：`python -m unittest tests.test_updater -v`。

## 本地运行

双击 `Start-Omini-Desktop.cmd` 可启动桌面版。

```powershell
py -3.11 -m pip install -r requirements.txt
py -3.11 app.py
```

开发环境下，应用会优先从 `tools/` 查找下载引擎，找不到时使用 PATH 中的 `yt-dlp`、`aria2c`、`gallery-dl`、`spotdl`。FFmpeg 始终使用本机安装，可在「设置 → 本机 FFmpeg」检测或选择程序；路径留空时自动检测 PATH 和常见安装位置。

## AI 编程助手与 Codex 成员账号池

侧栏「AI 编程助手」包含 Codex、Gemini CLI、Antigravity 反重力、Claude Code 四套独立配置。选择指定代理、直连或继承环境；默认代理为 `http://127.0.0.1:7890`。检测或选择程序，保存配置并测试网络后点击「带此环境启动」。Codex 可选 CLI 或桌面版；CLI 打开独立 PowerShell 窗口，也可复制环境到自己的终端。已有客户端请先正常退出再启动，以便加载新环境。

「Codex 成员账号池」使用 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) `v8.0.35`：

1. 完整构建已带引擎；源码运行可点「安装代理引擎」，或运行 `py -3.11 scripts/fetch_cliproxyapi.py`。下载固定官方 Windows 版本并验证 SHA-256，许可与来源随引擎保留。
2. 设置本地端口和出口代理，点击「保存并启动服务」。默认只在 `127.0.0.1:8317` 提供带随机密钥的本地接口。
3. 逐个「登录并添加成员」，在浏览器切换到相应账号并完成登录；或导入 Codex `auth.json` / CLIProxyAPI 的 Codex OAuth JSON。重复导入同一账号更新凭据。
4. 调度可选「轮询分配（按会话）」「雨露均沾（逐请求均分）」「优先账号（按优先级用满）」「加权轮询（按权重分配）」。运行中点击「保存并应用调度」生效。雨露均沾关闭会话保持；均分请求数量时，各请求消耗额度可能不同。
5. 点击「成员优先级 / 权重」调整，或选中账号后「设为优先账号」。优先级仅在优先模式使用，其余模式自动按同级成员分配；权重用于加权轮询。启用会话保持时，已有会话继续按引擎的绑定规则使用原账号。
6. 点击「查询所选额度」或「查询全部额度」，查看各成员的 5 小时、周剩余百分比和重置时间。查询仅读取用量，不发起模型生成；全量查询最多并发 3 个账号。失败保留上次快照并标记，未返回的周期显示「未返回」，悬停查看查询时间与错误原因。
7. 读取模型并选择，在 Codex 标签选好 CLI / 桌面版和程序位置，然后点击「通过账号池启动 Codex」。该入口使用专用 `CODEX_HOME`，原有配置和会话目录保留。桌面版请先退出已有实例。

网络测试只检查传输和 HTTP 状态，不验证登录或发起模型生成；HTTP 401 标为网络可达，403/429/5xx 显示需检查。Claude Code 使用 HTTP/HTTPS 代理端口。代理环境仅作用于从本页启动的进程，系统代理设置保持原值。

设置与本地接口密钥由 Windows DPAPI 加密，保存在 `%APPDATA%/Omini工具箱/ai-assistants/settings.json`。OAuth 凭据按引擎原生格式保存在该目录的 `auths/`，专用 Codex 配置和会话在 `codex-pool/`。服务停止时清理临时运行配置；切换侧栏继续运行，完全退出工具箱时停止服务。成员登录需各自完成，发布包不含个人账号。

1.1.8 起停服时直接显示本地成员，重启后恢复上次额度（标记「上次」）、模型列表与选择、所选成员、标签和页面位置。代理与启动配置编辑后自动保存，未完成的输入作为加密草稿保留。勾选「启动工具箱时恢复上次运行的账号池」后，上次运行中的服务会恢复；手动停止后保持停止。

「操作记录」保存带时间的配置、调度、成员变更、额度查询、服务启停与助手启动记录，可导出全部记录 TXT。`state.json` 与 `history/` 使用 Windows 用户加密，配置与状态保留 `.bak`，成员凭据变更前在 `backups/credentials/` 保存加密备份。升级和卸载保留这些用户文件；旧版仅存在内存的日志没有历史文件。

验证：`py -3.11 -m unittest tests.test_ai_assistants tests.test_codex_quota tests.test_pool_scheduling tests.test_assistant_persistence -v`，覆盖真实引擎导入、启停、轮询、会话保持、OAuth 链接与取消、参数传递、重启恢复和记录保存。源码与 EXE 都支持 `--self-test-ai-assistants`，使用临时目录检查完整侧栏、后台运行、主题、退出清理与重启恢复。

## 打包

### Windows 安装版

本地安装包位于 `dist-installer-1.2.2/Omini工具箱-1.2.2-Setup.exe`，正式发布时 GitHub 附件名为 `Omini-Toolbox-1.2.2-Setup.exe`。双击运行中文安装向导，可选择安装目录并创建桌面 / 开始菜单快捷方式；完整依赖和同步引擎自动安装。

默认安装到当前用户的 `%LOCALAPPDATA%/Programs/Omini工具箱/`，无需管理员权限。可从 Windows「已安装的应用」或开始菜单卸载。卸载保留 `%APPDATA%/Omini工具箱/` 中的个人设置、设备身份，以及同步目录中的文件。升级前从托盘退出工具箱，再运行新安装包。

已有完整 `dist-sync-1.2.2/Omini工具箱/` 发布目录时，使用 Inno Setup 6.7.3+ 执行 `./scripts/build_installer.ps1` 生成安装包；也可用 `-Compiler` 指定 `ISCC.exe` 路径。版本默认读取 `app_version.py`，指定版本时须与源码一致。

### 开发用目录发布包

```powershell
./build.ps1
```

发布结果在 `dist/Omini工具箱/`。请保留该目录中的 `Omini工具箱.exe`、`_internal/` 与 `tools/`，不要单独移动 EXE。当前源码版本为 `1.2.2`。

1.1.6 移除内置浏览器核心与随包 FFmpeg，备忘录替换为原生离线 TXT 笔记。网页统一使用系统浏览器；安装器继续采用 LZMA2 高压缩。构建脚本自动排除 `tools/` 中残留的 FFmpeg 文件，无需手动删除旧开发工具。覆盖升级会清理旧版安装目录中的浏览器运行库和 FFmpeg，个人数据目录保留。

`build.ps1` 下载 yt-dlp、Syncthing 与 CLIProxyAPI 的官方 Windows 发行版、复制本机 aria2c，并将图库和 Spotify 引擎打成独立 Windows 程序。构建后可运行 `py -3.11 scripts/verify_compact_release.py "dist-sync-1.1.6/Omini工具箱" --report verification/compact-release.json --ffmpeg "本机安装目录/ffmpeg.exe"`，验证 TXT、外部浏览器入口、媒体转换、实际下载和账号池。

应用窗口、托盘、侧栏品牌及 EXE 均使用 `assets/` 中的 Omini 图标；打包时会一并收集图标资源。

M3U8 页签通过 yt-dlp 的 HLS 原生分片下载器获取播放列表，支持并发下载与分片重试，并由 ffmpeg 合并为 MP4。文件名可以留空自动生成，或手动填写。

抖音公开视频由随包的 `tools/yt-dlp-plugins/omini/` 解析器优先读取公开移动分享页，验证播放地址有效后再交给 yt-dlp 下载、嵌入封面与元数据。普通公开视频通常无需 Cookie；分享页未提供视频或播放地址返回 404 时回到网页接口，并按需提示登录或验证。

支持手动选择 Netscape cookies.txt 或 `name=value;` Cookie 请求头文本（包含 `Cookie:` 前缀也可）。请求头在任务期间临时转换，结束后删除临时文件。Chrome/Edge 会话只在用户主动点击对应按钮时读取。

发布包必须保留 `tools/yt-dlp-plugins/`，否则抖音会退回原解析路径。窗口标题显示当前版本，便于与旧发布包区分。

支持抖音 `/note/` 图文分享链接：在视频页或图库页粘贴即可识别，下载全部公开图片，队列显示为“图文”。公开分享页缺少图片时，可在系统浏览器查看作品后手动导入公开图片地址；常规视频登录会话仍可通过用户选择的 Chrome/Edge 或 cookies.txt 提供。

新任务自动置顶、选中并显示实时日志；完成后会提示保存目录。“清空队列”一次停止全部在途任务、移除全部队列记录，保留下载文件和日志。清空前的记录自动备份到 `%APPDATA%/Omini工具箱/queue-backups/`；应用下次启动不会重新加载已清空记录。

按钮回归测试：`py -3.11 -m unittest tests.test_queue -v`。测试使用隔离的临时队列，不修改用户记录。

## 校园网自动登录

打开侧边栏「校园网自动登录」，填写账号和密码并点击「保存配置」。校园网页地址支持 `http://10.24.127.3/eportal/success.jsp?userIndex=...&keepaliveInterval=0`，也支持完整登录页地址；新配置默认指向 `success.jsp`，目标 Wi-Fi 为 `LEDE1`，服务名称按当前抓包留空。

「打开校园网页」优先打开当前会话的登录成功页。填写成功页完整地址后，程序先检查其中的会话是否在线；会话过期时重新获取当前连接的认证参数并登录，成功页随后使用新返回的 `userIndex`。浏览器在点击按钮时打开。

- 「立即登录」检查当前网络，已连通时跳过重复认证。
- 「连接目标 Wi-Fi 后自动登录」在应用启动及重新连接 LEDE1 时触发，每 10 秒检测一次；连接其他 Wi-Fi 时不发起认证。
- 「间隔定时」可设置 1～1440 分钟，默认 30 分钟；「每天定时」按本机时间每天触发一次。休眠或断网期间错过的任务在应用恢复且连接目标 Wi-Fi 后补检。
- 登录失败后间隔 60 秒重试，连续失败 3 次后暂停本轮自动尝试，重新连接目标 Wi-Fi 或保存配置可重新触发。
- 勾选「使用 Windows 本机加密保存密码」后，密码通过 DPAPI 加密存入配置；取消勾选并保存会删除已保存的加密密码。未保存的密码仅供本次应用运行使用。
- 勾选「关闭窗口后保留在系统托盘」可继续后台检测，双击托盘恢复窗口，右键选择「退出工具箱」结束。后台检测需要应用保持运行；本版不创建开机启动或系统计划任务。

每次认证获取当前连接的重定向参数和页面公钥，按校园网前端的 MAC 拼接、RSA 加密与二次编码流程提交。HAR 仅作为协议参考，未导入其中的密码或旧认证参数。若门户要求验证码，可点击「打开校园网页」。日志仅保留在内存中。

发布目录由 `./build.ps1` 生成到 `dist/Omini工具箱/`，请保留完整目录运行。功能回归：`py -3.11 -m unittest tests.test_class_timetable tests.test_douyin tests.test_timetable tests.test_campus tests.test_queue -v`。校园网测试使用隔离配置与本地模拟 HTTP 服务，并与 `verification/portal-security.js` 中门户原始 RSA 实现比对。

## 多电脑文件夹同步

侧栏「文件夹同步」管理本机身份、其他电脑和共享目录，内置官方 [Syncthing](https://syncthing.net/) `v2.1.6` 引擎。设备间连接使用证书加密；文件按块传输，支持断线续传、中文路径、多电脑共享和冲突副本。

### 首次配对

1. 在两台 Windows x64 电脑上运行完整发布包，进入「文件夹同步」，点击「启动同步服务」。每台电脑自动生成独立且持久的设备 ID，可自行设置电脑名称。
2. 在「电脑设备 → 添加电脑」中填入对方设备 ID；两台电脑都需要互相添加。连接地址默认 `dynamic`，也支持 `tcp://192.168.1.20:22000`，多个地址用逗号分隔。
3. 第一台电脑添加本机文件夹、选择需要共享的电脑，保存并复制共享 ID。
4. 第二台电脑添加自己的本机文件夹，填入相同共享 ID，选择第一台电脑。两台电脑的本地路径可以不同；首次同步会合并双方已有内容。
5. 默认「自动同步」，设备在线且文件夹启用后开始传输。系统防火墙弹窗出现时允许同步引擎联网。内网会尝试自动发现，外网使用直连或公共中继，实际连通性受网络环境影响。

### 已有 Tailscale 网络

在「添加电脑 / 编辑电脑」自行填写或选择同步对象，无需预设某一台电脑：

| 字段 | 填写内容 |
| --- | --- |
| 设备 ID | 对方**同步程序**显示的完整 ID，作为身份校验值 |
| 电脑名称 | 自定义名称，用于区分电脑 |
| 连接地址 | 对方 Tailscale IP（如 `100.101.102.103`）或 MagicDNS 名称；自动补成 `tcp://地址:22000` |
| 自定义端口 | 填写 `主机:端口` 或 `tcp://主机:端口`；IPv6 带端口使用 `[IPv6]:端口` |

可点击「读取 Tailscale 设备」并从下拉列表手动选择。读取不会覆盖已填内容或自动选定目标，选择后才会填入地址；设备 ID 仍需自行粘贴。也可完全手动输入，不必读取组网列表。本机身份栏支持读取和复制本机 Tailscale IP。

双方需要开启 Tailscale 和同步程序；Tailscale 网络访问规则、系统防火墙允许 TCP 22000（或自定义同步端口）。组网在线与同步服务在线是两个状态，对方只开启 Tailscale 时不会显示同步已完成。固定地址只用于主动连接到所填地址；手动额外加入 `dynamic` 可保留自动发现。程序不会更改 Tailscale 登录、网络策略或系统防火墙。

Mac / Linux 电脑可使用官方 Syncthing：在其管理界面添加此 Windows 电脑的设备 ID 与 Tailscale 地址，再添加对应共享 ID 的文件夹。Windows 发布包面向 Windows x64；跨系统通过同步协议互通。

连接地址格式参考 [Syncthing 配置文档](https://docs.syncthing.net/users/config)，MagicDNS 名称参考 [Tailscale 文档](https://tailscale.com/docs/features/magicdns)。

### 同步方式

- **自动同步**：监听文件变化，通常几秒后同步；每小时补充扫描。
- **手动同步**：平时暂停，点击「立即同步」执行扫描与传输，确认所有共享电脑完成本轮后自动暂停。对方也需启用对应文件夹；离线或尚未配对时保持等待，不以本机扫描结束冒充传输完成。
- **间隔定时 / 每天定时**：按 1～10080 分钟间隔或本机每天指定时间触发。计划持久保存，休眠或重启后补执行错过的一轮，完成后暂停。两边都使用定时时建议安排相同时间；接收端可保持自动模式。
- **暂停**：暂停此目录和定时任务；「立即同步」恢复原模式。停止服务会停止全部同步。退出时中断的手动任务下次保持暂停，定时任务按已保存计划恢复。

支持双向、仅发送、仅接收。双向模式会传播文件删除。来自其他电脑的覆盖或删除会由 Syncthing 的 staggered 版本控制保留到本地 `.stversions`，约保留 30 天；本机主动删除的文件依靠其他电脑的历史版本保留。并发编辑保留 `sync-conflict` 副本。版本文件占用磁盘空间；恢复旧文件时先暂停同步，从 `.stversions` 复制回原路径，再恢复同步。详见 [官方版本控制说明](https://docs.syncthing.net/users/versioning.html)。

勾选「关闭窗口后在托盘继续同步」可后台运行，从托盘右键退出才会结束同步服务。勾选「下次打开工具箱时启动同步」会随工具箱启动恢复服务；本版不创建 Windows 开机启动项。执行自动和定时任务需要工具箱运行，电脑之间同时在线时交换文件。

设备证书、索引和配置保存在 `%APPDATA%/Omini工具箱/sync/`，与系统已有 Syncthing 配置隔离。每台电脑自动生成自身身份；发布包不包含个人证书或配置，分发时使用完整发布包。移除设备或文件夹只移除共享配置，保留本机文件。应用通过带随机 API 密钥的本地回环 REST 管理独立引擎，多窗口实例锁防止争用同一配置。

开发环境获取引擎：`python scripts/fetch_syncthing.py`；脚本下载固定官方版本并校验发布方提供的 SHA-256，许可和来源随包保存在 `tools/syncthing-*`。`build.ps1` 已包含此步骤。

回归验证：`python -m unittest tests.test_folder_sync -v`。使用临时配置、仅本机直连的两台真实引擎测试双向传输、文件监听、删除与历史版本、并发冲突、手动完成暂停、设备身份重启恢复、定时补执行、暂停与界面按钮；不会读取已有同步目录。
